# GiveLife cloud message studio

Private administration UI with an external PostgreSQL-backed GoWA session. The laptop can turn off while the hosted service handles messages. Free hosting can sleep and restart, so continuous uptime is not guaranteed.

## Deployment

Create a Render Blueprint from this private repository in Wajdan's workspace. Use only the Free compute plan and a Neon Free database. No persistent disk or paid compute is configured. Do not add a payment method or enable usage-based upgrades. Render Free sleeps after inactivity and takes approximately a minute to wake. Free-plan quotas can stop availability; this is not an always-on production service.

`UI_ACCESS_KEY` is generated by Render and must remain secret. Read it from the service's Environment page and enter it into the studio login on your own devices. Do not put it in source code or URLs.

Set `DB_URI` to the private Neon connection URI with TLS enabled. Open the deployed UI, select WhatsApp, get the QR, and scan once from WhatsApp Linked devices. The cloud is a separate linked device; laptop credentials are not uploaded. PostgreSQL preserves the WhatsApp session and studio records. The poster is included with the application; temporary files can be recreated after restarts.

The GoWA API binds only to loopback. The public UI requires a bearer access key for data and sending. The optional private Sites frontend is allowed through CORS only at its declared origin.

The cloud does not start the local campaign bot, periodic donor checking, or DM batches. Buttons explicitly initiate group sends. Five-group sends use 60-second gaps, with a minimum 15-minute interval in the same group. Failed or uncertain sends are not retried automatically.

## Validation

Python syntax, frontend syntax, authentication, caption preservation, and Render schema can be checked locally. An actual Docker build and live WhatsApp send must be verified after deployment; no paid resource is created just by committing these files.
