# Chat logic reliability, 27 October 2026

This change strengthens the current Python/DeepSeek architecture; it does not retrain the model or change campaign captions.

- Preview, show, draft and review requests cannot authorize immediate sends. They bypass the direct command sender. Reading schedules remains available.
- Single-quoted commands are treated as data; apostrophes in ordinary instructions are preserved.
- Group exclusions are resolved before aggregate groups expand. Both direct commands and AI callbacks enforce the resulting list. Contact lookup cannot re-authorize an excluded group. Empty or unclear exclusions require a clear recipient instead of falling back to the previous group.
- Retrieved context accepts legacy JSON-text lists, ignores malformed records and copies entries before truncating them. Preparing a model request no longer modifies the memory supplied to it.
- Malformed tool-call collections, mixed valid/invalid calls and duplicate IDs are rejected before any tool in that response executes.
- A read-only lookup does not justify a new completion claim. Unsupported first-person or standalone completion claims are replaced with an honest lack-of-confirmation response.
- Model/API failures return a structured reply and diagnostics. Already completed edits remain reported if the next model call fails. Successful argument repair clears the obsolete error for that tool.

Validation: 151 Python tests passed, including 17 new regression tests. All three JavaScript suites passed (UI behavior, draft-loading gate, connection refresh). The Python suite uses isolated state, mocked model responses and fake WhatsApp transports. No real messages were sent by these tests. No live-model evaluation was run in this change, so natural-language accuracy remains model-dependent. Complex preview-and-send requests beginning with preview/review are deliberately conservative and require a separate explicit send instruction. Existing uncertain-send protection, stale-instruction guards, scheduling, DM composition and timers remain covered by the suite.

## Follow-up: edits and exact previews

Shared draft-task detection now authorizes general edit families (move a hook, replace a repeated line, change paragraphs, shorten, reword, and polite follow-ups), rather than requiring the word message in every instruction. The model is nudged to execute a clear requested edit with the full revised caption, instead of asking again. A requested rewrite must save before any send tool executes. Superseded edits are checked again inside the draft write lock. Saving one caption is serialized so a simultaneous save of the other caption does not lose it.

A get_message read tool and a direct preview path return exact saved captions, including formatting and blank lines, without a model call, Auto commentary or send suggestions. Generic Show uses the active Group/DM view supplied by the client. Show a new message requests an actual rewrite that retains owner updates, instead of resetting to a stock template. Previewing remains read-only. Draft context omits unrelated Auto/rhythm summaries and emphasizes recent owner instructions for pronoun resolution. Instructions require attribution for new owner-reported medical updates and prohibit invented clinical progression.

New regressions cover permission families, quoted logs, active-view exact reads, clear-edit execution, unsaved-edit reporting, stale saves, and edit-before-send order. Additional live-model sandbox cases cover a parent-reported hook, replacing an old line, and preserving the reported update in a fresh caption. General language understanding, originality and medical factuality still depend on the model; these changes do not constitute training or a guarantee of perfect performance. Auto continues to use built-in caption variations; manual send buttons use the saved caption. The assistant must not confuse these content sources.

## Follow-up: persistent draft tasks and contextual chat actions

The send worker previously rotated the saved caption after a successful manual group send, including a chat test send. Manual jobs now preserve their exact caption. The automatic engine retains its existing variation behavior. A persistent draft workflow binds current caption hash, intended production group, poster/text-only mode and total line limit. Test first does not change the production destination. Generic Send now prefers this task and refuses to use an unrelated old recipient if the task has none. Amount updates preserve an active custom draft while updating remaining amount and donation-option counts. Direct editor changes invalidate older suggestion buttons.

Chat now shows up to three server-issued next steps above the composer: View message, Send test, and Send to the selected group; when none is chosen, Choose group replaces the production send. No dashboard suggestion section was added. Displaying buttons never sends. Clicking sends only the stored, hash-checked caption, destination and media mode. Rapid taps share one request; the action token and persisted job prevent replay after a receipt. Old tokens, changed drafts, invented action IDs, hold and a disconnected WhatsApp cannot send. The frontend uses the existing authenticated connection layer and rejects stale suggestion refreshes. Both chat surfaces share action locks.

An explicit total line cap counts newline-delimited lines, including blanks; it does not guarantee visual line count across device widths. Manual edits may override that cap. Caption-save replies show the actual saved text and poster mode. Referential phrases such as this hadith message are treated as saved-caption requests, rather than literal outgoing text. Poster choices are preserved across follow-ups and can be explicitly changed.
